# 电子书阅读器 需求分析文档

## 一、项目背景与目标

### 1.1 项目背景
在日常学习和阅读中，很多人喜欢用电脑看电子书，但系统自带的文本编辑器体验很差，没有翻页、进度记忆、字号调节等功能。一个轻量、简洁的网页版电子书阅读器，可以解决这个问题。

### 1.2 项目目标
开发一个网页版 TXT 电子书阅读器，实现：
1. 上传本地 TXT 文件并解析
2. 分页展示文本内容
3. 调节字号、行间距
4. 记录阅读进度，下次打开自动恢复

### 1.3 项目价值
| 维度 | 价值 |
|------|------|
| 便捷 | 打开网页就能用，不需要安装软件 |
| 轻量 | 纯前端实现，加载快，占用资源少 |
| 隐私 | 文件本地解析，不上传服务器，保护隐私 |
| 免费 | 完全免费使用，无广告 |

## 二、用户与场景分析

### 2.1 目标用户画像
| 用户类型 | 特征 | 使用频率 | 技术熟练度 |
|----------|------|----------|------------|
| 学生 | 看教材、小说、资料 | 高频 | 中 |
| 上班族 | 看行业报告、技术文档 | 中频 | 中高 |
| 普通读者 | 看小说、散文 | 高频 | 低 |

### 2.2 典型使用场景
**场景一：学生看教材**
> 大学生小王下载了一本 TXT 格式的教材，想用电脑看，但系统记事本没有格式，看起来很累。打开网页版阅读器，上传文件，调节字号和行间距，舒服地阅读。

**场景二：上班族看报告**
> 小李收到一份 TXT 格式的行业报告，想快速浏览。打开阅读器，上传文件，滚动阅读，看完关掉就行，不需要保存文件。

**场景三：睡前看小说**
> 小张晚上用电脑看小说，看到一半要睡觉了。关掉网页，第二天打开，自动跳到上次看到的位置。

### 2.3 用户痛点总结
1. **界面简陋**：系统记事本排版差，长时间阅读眼睛累
2. **功能缺失**：没有字号调节、行间距调节、进度记忆
3. **文件笨重**：需要安装专门的阅读器软件，占用空间
4. **隐私问题**：在线阅读器可能上传文件到服务器

## 三、功能需求分析

### 3.1 功能需求清单

#### （1）文件上传与解析
| 编号 | 需求描述 | 必要性 |
|------|----------|--------|
| FR-01 | 支持上传本地 TXT 文件 | 必须 |
| FR-02 | 上传后自动解析文本内容 | 必须 |
| FR-03 | 支持 UTF-8 编码的 TXT 文件 | 必须 |
| FR-04 | 上传失败时提示错误信息 | 重要 |

#### （2）阅读展示
| 编号 | 需求描述 | 必要性 |
|------|----------|--------|
| FR-05 | 分页展示文本内容 | 必须 |
| FR-06 | 每页显示固定行数 | 必须 |
| FR-07 | 支持翻页按钮切换上下页 | 必须 |
| FR-08 | 支持键盘左右方向键翻页 | 重要 |
| FR-09 | 显示当前页码/总页数 | 必须 |
| FR-10 | 显示阅读进度百分比 | 重要 |

#### （3）阅读设置
| 编号 | 需求描述 | 必要性 |
|------|----------|--------|
| FR-11 | 支持调节字号大小 | 必须 |
| FR-12 | 支持调节行间距 | 重要 |
| FR-13 | 支持切换背景颜色（白色/深色） | 可选 |
| FR-14 | 设置自动保存到本地 | 重要 |

#### （4）进度记忆
| 编号 | 需求描述 | 必要性 |
|------|----------|--------|
| FR-15 | 自动记录当前阅读位置 | 必须 |
| FR-16 | 下次打开自动恢复到上次位置 | 必须 |
| FR-17 | 按文件名区分不同文件的进度 | 重要 |

### 3.2 功能优先级（MoSCoW）
- **Must have（MVP）**：FR-01~03、FR-05~07、FR-09、FR-11、FR-15~16
- **Should have（v1.1）**：FR-04、FR-08、FR-10、FR-12、FR-14、FR-17
- **Could have（v1.2+）**：FR-13
- **Won't have（本期）**：EPUB 支持、书签、目录、搜索

## 四、界面需求分析

### 4.1 设计原则
- **简洁**：白底 + 单一主色，减少视觉噪音
- **专注**：核心操作（翻页）一屏可达
- **舒适**：适合长时间阅读的排版

### 4.2 界面组成
**（1）上传区域（初始状态）**
- 位置：页面居中
- 元素：大图标 + 提示文字 + 上传按钮
- 交互：点击上传按钮选择文件，或拖拽文件到页面

**（2）阅读区域（阅读状态）**
- 位置：页面居中，最大宽度 800px
- 顶部：页码、进度条
- 中间：文本内容区
- 底部：上一页/下一页按钮
- 右侧：设置面板（字号、行间距、主题）

### 4.3 视觉规范
| 项 | 规范 |
|----|------|
| 主色 | #4A90D9 |
| 成功 | #22C55E |
| 危险 | #EF4444 |
| 圆角 | 卡片 8px，按钮 6px |
| 字体 | 系统 sans-serif，16px 基准 |
| 间距 | 8px 栅格 |

## 五、技术可行性分析

### 5.1 技术选型
| 层 | 选型 | 理由 |
|----|------|------|
| 前端框架 | 原生 HTML/CSS/JS | 纯静态，不需要构建工具 |
| 样式 | CSS3 | 简单轻量 |
| 文件解析 | FileReader API | 浏览器原生，本地解析 |
| 进度存储 | localStorage | 浏览器本地存储 |
| 部署 | GitHub Pages | 免费静态托管 |

### 5.2 关键技术难点与对策
| 难点 | 说明 | 对策 |
|------|------|------|
| 分页计算 | 不同字号、行间距下每页能放多少行不一样 | 动态计算每页行数，根据容器高度和行高 |
| 大文件处理 | 大 TXT 文件可能几十 MB | 流式读取，分页渲染，不一次性加载全部 |
| 进度记忆 | 刷新后恢复阅读位置 | 记录当前页码和文件哈希，存到 localStorage |

### 5.3 可行性结论
- **技术可行**：所有核心能力均有成熟浏览器 API 支持
- **成本可控**：纯前端实现，无服务器成本
- **风险可控**：主要风险是兼容性问题，主流浏览器都支持
